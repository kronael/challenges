# Sources

- [LeetCode 84 — Largest Rectangle in Histogram](https://leetcode.com/problems/largest-rectangle-in-histogram/)
  is this problem with the book drawn as a bar chart: read `quantities[i]` as the
  height of bar `i` and a sweep as a rectangle resting on the axis. Same
  reduction, same stack, `n <= 10^5` instead of `10^6`.
- CSES Problem Set — *Advertisement*
  ([task 1142](https://cses.fi/problemset/task/1142)) is the same problem again,
  and the [USACO Guide's solution page for it](https://usaco.guide/problems/cses-1142-advertisement/solution)
  works through both shapes discussed in `03.md`: the two boundary arrays from
  separate scans, and the single pass that reads the left boundary off the stack.
  It also names the `-1` closing height as the way to avoid special-casing the
  drain.
- USACO Guide, Gold — *Stacks* (the monotonic-stack module): the nearest-smaller
  scan, the amortized argument that each index is pushed and popped once, and the
  step from one boundary per element to a maximal span between two of them.
- [LeetCode 907 — Sum of Subarray Minimums](https://leetcode.com/problems/sum-of-subarray-minimums/)
  computes the same two boundaries for every element and sums
  `value * left_width * right_width` instead of maximising a single product.
  Worth doing next, because there the strict/non-strict asymmetry from `02.md`
  stops being a convenience and becomes mandatory: a plateau double-counts
  runs unless exactly one side is strict.
- [LeetCode 1793 — Maximum Score of a Good Subarray](https://leetcode.com/problems/maximum-score-of-a-good-subarray/)
  and
  [LeetCode 1856 — Maximum Subarray Min-Product](https://leetcode.com/problems/maximum-subarray-min-product/)
  are the same `minimum * span` product with one index pinned inside the span, and
  with the span weighted by a prefix sum instead of counted. Both fall to the
  candidate-per-limiting-element reduction from `01.md`.
- [LeetCode 85 — Maximal Rectangle](https://leetcode.com/problems/maximal-rectangle/)
  is where the technique earns its keep: a binary matrix, largest all-ones
  rectangle. Build each row's column-height array incrementally and run this
  challenge's scan once per row, for `O(rows * cols)` overall. Recognising that a
  2-D problem is `n` copies of this 1-D one is the payoff for having the 1-D case
  in hand.
- `59-medium-price-undercut` in this repo is the same stack answering half the
  question — one boundary, as a distance, per element — and
  `13-medium-sliding-window-max` is the contrast worth holding next to it: there
  an index leaves the structure either because it was beaten *or* because it aged
  out of a fixed window, so the structure is a deque of bounded size and reports
  an aggregate per window. Here nothing ages out, an index leaves only when it is
  blocked, the structure can hold the whole book at once, and what a departure
  produces is a completed rectangle.
