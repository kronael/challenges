# Hint 1

> Spoilers. Open only when stuck, and only one file at a time.

**A sweep looks like two choices, and one of them is not really a choice.** Fix
the run of levels. Every level in it has to cover `q`, so `q` can go up to the
shallowest level in the run and no further — and the total is `q` times the
number of levels, so you always want `q` as large as that run allows. The
quantity is decided the moment the run is:

```
best total for a run = (shallowest quantity in it) * (number of levels in it)
```

`q` is gone. What is left is a choice of run, and there are `n(n+1)/2` of those —
5 * 10¹¹ at `n = 1000000`, which is out of reach even if evaluating one were
free. So the run cannot be the thing you enumerate either.

**Enumerate the limits instead of the runs.** Look at the run that wins.
Somewhere inside it sits a level that is its shallowest — the level that capped
`q`. Now try to widen that run: if the level just outside rests *at least* as
much as that shallowest level, adding it leaves `q` untouched and raises the
count, so the total can only go up. Keep widening while that holds, and you still
have a winning run — one that is now as wide as its own shallowest level permits,
in both directions.

That is the reduction the whole problem turns on. Every level `i` contributes
exactly one candidate — **the widest run in which level `i` is the shallowest**,
worth `quantities[i] * (that run's length)` — and the answer is the best of those
`n` candidates. No level is left out: the winning run's own shallowest level
produces it.

`n` candidates instead of `n²/2` runs. The question is now a much narrower one:
where does level `i`'s run have to stop?
