# Approach — Tarjan's bridge algorithm: one walk, two numbers per venue

The links you are asked for are the **bridges** of the undirected graph, and
Tarjan's bridge-finding algorithm gets all of them out of a single depth-first
search. Two arrays, filled in one pass:

- `order[v]` — the step at which the search first reached `v` (its *discovery
  time*).
- `reach[v]` — the smallest `order` reachable from `v`'s subtree using subtree
  tree-edges plus at most one back edge (its *low-link value*).

`reach[v]` is `min(order[v], min over back edges v→w of order[w], min over
children c of reach[c])`, and the children's contributions land as the search
backs out of each child.

**The criterion.** For a tree edge `parent → v`, that edge is a bridge exactly
when

```
reach[v] > order[parent]
```

Nothing in `v`'s subtree reaches `parent` or anything discovered before `parent`
by any other route, so cutting the edge cuts the subtree off. If instead
`reach[v] <= order[parent]`, some back edge out of the subtree lands on `parent`
or above it, closing a loop through the edge. Non-tree edges are never bridges:
each one closes a loop by construction.

**Track the link you entered on, not the venue.** Store `entered[v]` = the
*position in `links`* of the edge used to reach `v`, and skip exactly that one
adjacency slot while scanning `v`'s links. Skipping "any neighbour equal to the
parent venue" is wrong: with two links between the same pair, that test throws
away both, `reach[v]` never sees the second one, and both get reported as
critical. Give every adjacency slot the position of the link it came from and the
duplicates take care of themselves — the second link is an ordinary back edge to
the parent, so `reach[v] <= order[parent]` and neither link is a bridge.

**Iterate; do not recurse.** Keep an explicit stack of venues and a per-venue
cursor into that venue's adjacency slots. Push a venue when you first reach it,
pop it when its cursor is exhausted, and do the `reach` merge plus the bridge test
at pop time, against whatever is now on top of the stack.

```
build adjacency: for each link i = (u, v), give u a slot (v, i) and v a slot (u, i)

order[*] = -1;  entered[*] = -1;  cursor[v] = first slot of v;  step = 0
for root in 0 .. n-1:
    if order[root] >= 0: continue
    order[root] = reach[root] = step; step += 1
    stack = [root]
    while stack:
        v = stack.top()
        if cursor[v] has a slot left:
            (w, link) = next slot of v; advance cursor[v]
            if link == entered[v]: continue          # the one link we came in on
            if order[w] < 0:                         # tree edge
                entered[w] = link
                order[w] = reach[w] = step; step += 1
                stack.push(w)
            else:                                    # back edge
                reach[v] = min(reach[v], order[w])
        else:
            stack.pop()
            if stack:
                p = stack.top()
                reach[p] = min(reach[p], reach[v])
                if reach[v] > order[p]: critical.append(entered[v])
```

`entered[root] = -1` and link positions are `>= 0`, so a root never skips a slot,
which is what makes the root's own tree edges get tested like everyone else's.

**Loop over every root.** The network may be in several pieces, so restart the
walk from every venue that still has `order == -1`. Venues with no links are
their own piece and contribute nothing. Nothing else about the algorithm changes:
each piece is searched independently and a bridge is a bridge within its own
piece.

**Adjacency layout.** Build it flat rather than as a list of lists: count each
venue's degree, prefix-sum the counts into a `start` array, then fill two parallel
arrays `slot_to` and `slot_link` in one pass over `links`. That gives contiguous
slots per venue, one integer of state per venue for the cursor, and no per-venue
container. (`golden/main.py` does exactly this.) A neat alternative when you
control the numbering: store each link twice at slots `2i` and `2i+1` so that
`slot >> 1` is the link position and `slot ^ 1` is the reverse slot.

**Collect and sort.** Bridges come out in the order venues are popped, which is
not increasing link position, so sort the collected positions before printing.
That is `O(k log k)` on the answer, well under the cost of the walk.
