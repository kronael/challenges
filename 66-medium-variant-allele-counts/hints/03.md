# Approach — eight running sums the input makes exact

A dosage is `k / 4096` for an integer `k` from `0` to `8192`, so every sum of
dosages is `K / 4096` for an integer `K` no larger than `8192 × 200000`, which is
below `2^31`. A double carries 53 significant bits, so every partial sum along
the way, in any grouping, is exactly representable: no addition ever rounds.
Different orders then produce the identical double, and the identical twelve
printed digits. The compiler cannot know this about your input; you can, so you
write the lanes yourself.

Keep eight separate sums, one per position in a block of eight samples, add
them together once at the end, and let a passing sample contribute its dosage
and a failing one contribute zero:

```c
double lane[8] = { 0 };
long long kept = 0;
size_t i = 0;
for (; i + 8 <= n; i += 8) {
	for (size_t j = 0; j < 8; j++) {
		const int keep = (depth[i + j] >= dmin) & (quality[i + j] >= qmin);
		lane[j] += dosage[i + j] * keep;
		kept += keep;
	}
}
/* the last n % 8 samples, then lane[0] + lane[1] + ... + lane[7] */
```

Each `lane[j]` still adds in order, so the compiler reorders nothing; it only
has to notice that the eight chains are independent. gcc 12.2 turns the inner
loop into packed compares, `vcvtdq2pd` to make the `0`/`1` factors doubles, and
two `vmulpd` / `vaddpd` pairs over four doubles each; clang 21 folds each
multiply and add into one `vfmadd231pd`. `make vec` grades both at 0.00 scalar
instructions per sample.

## The shape of the lane update matters

Measured with the fixture `make vec` traces, `x86-64-v3`, `-O3`:

| inner update | gcc 12.2 | clang 21 |
|---|---|---|
| `lane[j] += dosage[i + j] * keep;` | vectorized | vectorized |
| `if (keep) lane[j] += dosage[i + j];` | scalar | scalar |
| `lane[j] += keep ? dosage[i + j] : 0.0;` | **wrong answers** | scalar |

The last row reads `dosage[i + j]` only when `keep` is true, so packing it takes
a masked load. clang declines and stays scalar. gcc 12.2 miscompiles it: its
`vmaskmovpd` for dosages 4–7 gets the mask of samples 0–3, so a sample in the
upper half counts only when the sample four before it passes too. That drops
dosages and fails fixtures `07`, `12`, and `14` at `-O3`; `-O2` and
`-fno-tree-loop-vectorize` keep the loop scalar and get it right. Read the
dosage unconditionally — `const double d = dosage[i + j];`, then
`lane[j] += keep ? d : 0.0;` — and both compilers vectorize the select
correctly.

The multiply is exact here — a dosage times `1` is itself, times `0` is `+0.0` —
so it is not a compromise.

Explicit AVX2 intrinsics work in both compilers and are what `golden/` uses:
eight `int32` compares in one `_mm256_cmpgt_epi32` each, the mask widened to two
`__m256d` masks with `_mm256_cvtepi32_epi64`, and two `__m256d` sums fed through
`_mm256_and_pd`.

## Rust and Go

**Rust** (rustc 1.97): over `dosage.chunks_exact(8)` zipped with the depth and
quality chunks, the multiply form and `lane[j] += if keep { d } else { 0.0 }`
both vectorize; `if keep { lane[j] += d; }` stays scalar, as it does in C.
`std::arch::x86_64` intrinsics work too: `make test` and `make vec` both build
with `-C target-cpu=x86-64-v3`, so an `unsafe` block can call them directly.

**Go**: the compiler does not vectorize anything on its own, so write the lanes
with `simd/archsimd`. Load eight depths and qualities with
`archsimd.LoadInt32x8Array((*[8]int32)(depth[i:]))`, combine the two
`Greater` masks with `And`, turn the result into `Int32x8` lanes of `0` and `-1`
with `ToInt32x8`, and widen each half with `GetLo()` / `GetHi()` and
`ExtendToInt64()`. `NotEqual` against a zero `Int64x4` gives the `Mask64x4`
that `Float64x4.Masked` needs, and `Float64x4.Add` keeps the two running sums.

## Things that go wrong

- **`float` lanes.** Eight `float` lanes fit one register where four doubles do,
  and a float has 24 significant bits. A partial sum past `4096` can no longer
  hold a step of `1/4096`. Fixture `14` puts 16500 samples of dosage `2` ahead of
  2000 odd multiples of `1/4096`, so every one of eight float lanes is past
  `4096` when the fine fractions arrive, and they are rounded away.
- **Summing into one total inside the block.** `ac += dosage[i + j] * keep` over
  a block of eight is the original chain with a different loop shape: the adds
  still form one sequence the compiler may not split.
- **The tail.** `n` is rarely a multiple of eight. Fixtures `09`, `10`, `11`, and
  `12` have `n = 7, 8, 9, 1023`.

An integer route is just as exact: `dosage × 4096` is an integer below `2^14`,
so converting and summing integers gives `K` directly.
