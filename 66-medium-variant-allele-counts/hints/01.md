# Hint 1

> Spoilers. Open only when stuck, and only one file at a time.

**The filter is not the problem.** Two compares and a count of the samples that
pass them are integer work, and the compiler splits an integer count across
lanes without being asked: integer addition is associative, so eight partial
counts added at the end give the same number as one count kept all the way.

Look at the one operation in the loop that is not integer: the running total of
`dosage`. Ask what the compiler is allowed to do with `ac += dosage[i]`, and
what it would have to change about those additions to run eight of them at
once.

Confirm that this is where it stops. clang 21 says so in as many words:

```
clang -O3 -march=x86-64-v3 -Rpass-analysis=loop-vectorize -S solution.c
remark: loop not vectorized: cannot prove it is safe to reorder floating-point operations
```

gcc 12.2 is less direct: `-fopt-info-vec-missed` names the branch first, and
once the loop is branch-free it still refuses the sum.
