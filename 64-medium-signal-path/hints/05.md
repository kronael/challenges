# Sources

- [LeetCode 124 — Binary Tree Maximum Path Sum](https://leetcode.com/problems/binary-tree-maximum-path-sum/)
  is this problem with the hierarchy drawn as a binary tree and `pnl[i]` as a node
  value: same reduction, same two numbers per node, same clamp at zero. It is
  tagged Hard there and sits at medium here on purpose — the reduction in `01.md`
  is one step, and everything after it is edge cases (the clamp, the one-arm
  restriction, an answer that is not at the root, a chain of at least one node) plus
  the depth of the input, which LeetCode's `n <= 3 * 10^4` never forces you to
  think about.
- [LeetCode 543 — Diameter of Binary Tree](https://leetcode.com/problems/diameter-of-binary-tree/)
  is the same candidate-versus-propagated split with edge counts in place of sums.
  Worth doing first if `03.md`'s two lines still feel arbitrary: because edge counts
  are never negative the clamp disappears, which leaves only the "both arms at the
  turn, one arm upward" asymmetry to hold in your head.
- [LeetCode 687 — Longest Univalue Path](https://leetcode.com/problems/longest-univalue-path/)
  adds a condition on which arms may be joined at the turn, and
  [LeetCode 1522 — Diameter of N-Ary Tree](https://leetcode.com/problems/diameter-of-n-ary-tree/)
  is what the same split becomes when a node has many children: keep the two best
  child gains rather than left and right. Both make the point that `left`/`right` is
  incidental — the recurrence only ever wanted "the best two" and "the best one".
- CSES Problem Set — *Tree Diameter* ([task 1131](https://cses.fi/problemset/task/1131))
  and *Tree Distances I* ([task 1132](https://cses.fi/problemset/task/1132)) are the
  same combine-the-two-best-children step over an unrooted tree at `n = 2 * 10^5`,
  where you have to root it yourself first. `1132` is also the standard doorway to
  rerooting, which is the technique for when *every* node needs the answer rather
  than one global maximum.
- USACO Guide's tree-diameter material covers the same step, including the
  amortized argument that a single traversal touching each node once is enough and
  the warning about recursion depth on a path-shaped tree.
- [LeetCode 1372 — Longest ZigZag Path in a Binary Tree](https://leetcode.com/problems/longest-zigzag-path-in-a-binary-tree/)
  is the instructive near-miss: two values per node again, but both of them travel
  upward and neither is a candidate answer on its own. Comparing it with this
  challenge is the cleanest way to see that "two numbers per node" is not one
  pattern — what matters is which of them the parent is allowed to read.
- `01-easy-max-subarray` in this repo is this problem on recipe
  `09_large_skewed_chain`. A hierarchy that is one line has no turns, so every chain
  is a contiguous run of the line and the answer is its maximum subarray sum —
  Kadane's "restart when the running total drops below zero" *is* the
  `max(0, down[c])` clamp, arrived at from the other side. That is also how the
  seeded answer for that recipe was checked independently of `golden/main.py`.
- `50-hard-tree-sequence-likelihood` and `60-medium-venue-ancestor` are the other
  tree challenges here and neither overlaps this one; `03.md` sets out why.
  `61-hard-critical-venue-links` is the one to reread for the depth-first walk
  flattened onto an explicit stack, which is the same fix the `500000`-desk line
  needs here.
