# Complexity — the same cells in a different order

`golden/solution.c` and the row-by-row loop of hint 2 run the same recurrence
over the same `|s|·|t|` cells in `O(|s|·|t|)` time. The golden does more work:
it builds a 20-row profile first, and every column adds a shift, four
shift-and-max steps, and a second pass over its vectors. It wins because no
lane waits for another inside a vector.

`make vec` grades the golden at 0.28 scalar and 0.82 packed instructions per
residue pair under gcc 12, and 0.15 and 0.79 under clang 21.

**Setup counts.** `make vec` divides by residue pairs, but it counts
everything `solve` retires, including the work before the first column. On
`vec.in`, a step that costs 40 scalar instructions per residue of `s` and `t`
costs 40 · 810 / 164,000 ≈ 0.2 per pair. Under gcc, about 0.25 of the golden's
0.28 is its profile: a load, a store, and index arithmetic for each of 20
entries per row of `s`.

**Why not the lazy loop.** Farrar's lazy loop settles the strip tops by walking
the column again while the carried `X` still wins. In a global alignment the
rows below the alignment's path are best reached by one gap from it, so on a
protein aligned with a diverged copy of itself the carry keeps winning down
every strip, and the lazy loop walks the column up to sixteen more times. The
exact entry values cost the same on every column.
