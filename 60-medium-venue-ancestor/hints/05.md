# Sources

- [LeetCode 236 — Lowest Common Ancestor of a Binary Tree](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree/)
  is this problem for a single pair, given child pointers instead of parent
  pointers, and
  [LeetCode 235](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-search-tree/)
  is the search-tree variant where the key comparison replaces the climb.
  [LeetCode 1650](https://leetcode.com/problems/lowest-common-ancestor-of-a-binary-tree-iii/)
  is the parent-pointer form, and the two-pointer trick there is the same
  equalise-then-walk idea.
- CP-Algorithms — *Lowest Common Ancestor*: the same equalise-and-climb
  preprocessing, then the O(log n) and O(1) per-query structures built on top of
  it. Read the first section; the rest is the tooling this challenge's limits do
  not need.
- USACO Guide, Platinum — *Binary Jumping*: where to go next, once the plain
  climb is second nature and the batch gets big enough that O(depth) per pair
  stops being affordable.
- CLRS, *Introduction to Algorithms* — the tree-terminology chapter for
  ancestor/descendant/depth, and Tarjan's offline LCA (union-find over a single
  DFS) as the classic alternative when every pair is known in advance.
