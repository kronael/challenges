# Approach — depth once, then equalise and climb together

Two phases. The first runs once for the whole batch, the second once per pair.

**Phase 1 — the depth of every venue, iteratively.** Walk up from each venue
until you reach a venue whose depth is already known (or fall off the root), then
write the collected chain back down from that anchor:

```
depth[v] = -1 for all v
for start in 0 .. n-1:
    chain = []
    node = start
    while node != -1 and depth[node] < 0:
        chain.append(node)
        node = parent[node]
    level = 0 if node == -1 else depth[node] + 1
    for venue in reversed(chain):
        depth[venue] = level
        level += 1
```

Every venue is appended to a chain exactly once over the whole loop — the second
time it is reached, its depth is already set and the walk stops there — so this is
O(n) in total, no matter how the venue numbers are arranged. It uses no recursion,
which matters: the hierarchy may be one 200000-venue line, and a recursive depth
walk overflows the stack (in Python it raises `RecursionError` well before that).
You do not need a children list, an adjacency structure, or a traversal order.

**Phase 2 — one pair at a time.**

```
if depth[a] < depth[b]: swap(a, b)
while depth[a] > depth[b]: a = parent[a]     # equalise
while a != b: a = parent[a]; b = parent[b]   # climb together
answer = a
```

Both edge cases fall out with no special handling. If `a == b` the two loops do
nothing and the answer is `a` itself. If `a` is on the route of `b`, the equalise
loop lands `b` exactly on `a` and the second loop does nothing.

**Do not build anything per pair.** No list, set, or dictionary of one venue's
ancestors: the two pointers already carry all the state a pair needs, and the
climb stops the moment they agree, so a pair whose answer sits one step away
costs one step instead of a walk to the root.
