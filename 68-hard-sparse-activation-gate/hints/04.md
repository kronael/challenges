# Complexity — the same answer from a different position computation

Both implementations are `O(n)` time and `O(n)` output. They run the same
compares on the same scores and leave the same values in the answer; only the
shape of the per-element position computation differs. `golden/` even adds work
the control never does: a movemask, a `pdep` / `pext` pair, a widen, a permute,
and a popcount per block of eight. It wins because it took the per-lane position
out of the loop-carried chain and turned it into a function of the mask, which
the hardware evaluates for eight lanes at once.

Measured on this box — Ryzen 9 5950X, `-O3 -march=x86-64-v3`, 200000 scores
drawn uniformly from ±10^9 with threshold `0`, best of 50 calls to `solve`:

| build | `golden/` | `rotten/` |
|---|---|---|
| gcc 12.2 | 23.6 µs | 541 µs |
| clang 21 | 28.3 µs | 524 µs |

Half the scores are kept at random, so the control's branch is also
unpredictable; the golden has no per-score branch at all.

`make vec` sees the difference without a clock, and stops tracing `rotten/` once
it passes the budget. Traced to the end on fixture `16`, `rotten/` retires 4.99
scalar instructions per score under gcc and 3.99 under clang, and `golden/` 0.01
under both.

## Other forms under gcc 12.2

- The control stays scalar at `-march=x86-64-v4` too. AVX-512 has
  `vpcompressd`, which packs one vector in one instruction, and gcc 12's
  vectorizer still reports `unsupported use in stmt` and emits no compress.
  The wall is the vectorizer's analysis, not the instruction set.
- The three-pass plain-C form — a `keep[i]` flag array, a prefix-sum array,
  then `out[pos[i]] = x[i]` for every `i` — vectorizes only its first pass.
  The prefix loop is a loop-carried dependence (`possible dependence between
  data-refs`), and the scatter store is refused too: `possible alias involving
  gather/scatter`, and with `restrict` pointers `unsupported data-type`, because
  AVX2 has gathers but no scatter. It is the right decomposition at the wrong
  granularity: the prefix sum has to happen inside a vector, not across an
  array.

Inference kernels make this move all the time. A mixture-of-experts router
scores every token for every expert and then hands each expert the tokens it
won, packed densely and in order — that packing is this loop. Contextual
sparsity does the same to neurons: predict which ones fire, gather them into a
dense block, run only that block.
