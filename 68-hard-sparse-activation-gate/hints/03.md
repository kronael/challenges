# Approach — pack each vector with a permutation of its mask

This is stream compaction, and the classic parallel formulation has three
steps: flag every element, take the exclusive prefix sum of the flags, and
scatter each flagged element to its prefix sum. Inside one AVX2 vector the
three steps collapse into a compare, a bit mask, and a permute:

```c
const __m256i v = _mm256_loadu_si256((const __m256i *)(scores + i));
const __m256i above = _mm256_cmpgt_epi32(v, limit);
const unsigned m = (unsigned)_mm256_movemask_ps(_mm256_castsi256_ps(above));
const uint64_t bytes = _pdep_u64(m, 0x0101010101010101ull) * 0xff;
const uint64_t lanes = _pext_u64(0x0706050403020100ull, bytes);
const __m256i perm = _mm256_cvtepu8_epi32(_mm_cvtsi64_si128((long long)lanes));
_mm256_storeu_si256((__m256i *)(kept + k), _mm256_permutevar8x32_epi32(v, perm));
k += (size_t)_mm_popcnt_u32(m);
```

`m` holds the eight flags. Lane `j`'s exclusive prefix sum is
`popcount(m & ((1 << j) - 1))`, and the scatter "lane `j` goes to slot
`prefix(j)`" is the same thing as the gather "slot `s` takes the `s`-th set bit
of `m`" — which is a permutation index vector. Two ways to get it:

- A table of 256 rows, each the indices of that mask's set bits packed to the
  front. Build it once with the scalar append loop: the naive code runs 256
  times in total, never per element.
- BMI2, which `x86-64-v3` includes. `pdep` spreads the eight bits to one per
  byte, `* 0xff` widens each to a full byte, `pext` compresses the identity
  bytes `07 06 05 04 03 02 01 00` against them, and `vpmovzxbd` widens the
  bytes to lanes. `pext` is itself a compaction, just of bits, so the
  permutation is the identity compressed against the mask.

`vpermd` applies the permutation. The store writes all eight lanes at
`kept + k`, and only `popcount(m)` of them count: `k` advances by that many,
the next store or the scalar tail overwrites the rest, and the answer ends at
`k` before any that are left. `kept` is sized `n`, and the block store never
runs past it because `k ≤ i ≤ n - 8` inside the loop. The tail of `n mod 8`
scores stays scalar, exactly like the control. Across vectors the carry is the
scalar `k`: one add per eight scores instead of one per score.

`make vec` grades this at 0.01 scalar instructions per score. The mask
arithmetic alone is about one general-purpose instruction per score, but it
runs in iterations that load a vector, and `make vec` leaves general-purpose
work there out of the count.

## Rust and Go

**Rust**: the same intrinsics live in `std::arch::x86_64` —
`_mm256_cmpgt_epi32`, `_mm256_movemask_ps`, `_pdep_u64`, `_pext_u64`,
`_mm256_cvtepu8_epi32`, `_mm256_permutevar8x32_epi32`. `make test` and
`make vec` both build with `-C target-cpu=x86-64-v3`, so call them from an
`unsafe` block inside `solve`; `#[target_feature]` is neither needed nor
accepted by `make vec`. Measured with rustc 1.97: 0.01 scalar instructions per
score, against 5.55 for `scores.iter().copied().filter(...).collect()`.

**Go**: `simd/archsimd` has `Int32x8.Greater`, `Mask32x8.ToBits` for the eight
flags as a `uint8`, and `Int32x8.Permute` with a `Uint32x8` of indices. Go has
no `pdep`, so build the 256-row table of `[8]uint32` in `init` and load a row
with `archsimd.LoadUint32x8Array(&table[m])`. Advance `k` with
`bits.OnesCount32(uint32(m))`, which is one `popcnt`; `bits.OnesCount8` reads a
table, a scalar load per block. Write the kept scores back into `scores` and
return `scores[:k]`: every store lands at `k ≤ i`, on scores already loaded. A
fresh `make([]int32, n)` sends `solve` through the runtime's large-object
allocator, which `make vec` traces too, and its heap growth costs from 0.1 to 3
scalar instructions per score from run to run: about one run in ten fails.
Measured with Go 1.27.1: 0.00 scalar instructions per score in place, against
5.8 for an `append` loop into `make([]int32, 0, len(scores))`.
`Int32x8.Compress` does a block's pack in one instruction, but it is AVX-512
(`vpcompressd`), outside `x86-64-v3`, and `make vec` refuses it.
