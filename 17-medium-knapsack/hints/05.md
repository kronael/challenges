# Approach — read one row, write another

Keep two rows. Each item reads `best`, the answers for the items before it,
and writes `next`; budgets below the item's weight copy across unchanged; then
the two swap. Every budget of an item now depends only on the row before it,
so four budgets at once read exactly what one at a time would, and the ranges
the loop reads and writes never overlap.

```c
if (weight > capacity) continue;
memcpy(next, best, w * sizeof *next);
for (size_t c = w; c <= cap; c++) {
	const long long take = best[c - w] + v;
	next[c] = take > best[c] ? take : best[c];
}
/* swap best and next */
```

The update is a select, not a conditional store: every budget writes `next[c]`.
The lanes are 64 bits because the sums need them: the fixture's answer is
28806383737, past `2^31`. AVX2 has no 64-bit maximum, so it is a compare and a
blend; `_mm256_max_epi64` in C and `Int64x4.Max` in Go are AVX-512, which
`make vec` refuses.

| inner update | gcc 12 | clang 21 |
|---|---|---|
| one row, `if (take > best[c]) best[c] = take;` | scalar | scalar |
| one row, `best[c] = take > best[c] ? take : best[c];` | vectorized | scalar |
| two rows, as above | vectorized | vectorized |

clang checks that the range it reads, `best[0..cap-w]`, and the range it
writes, `best[w..cap]`, do not overlap. In one row they overlap for every item
no heavier than half the capacity, so clang runs its scalar copy.

**Rust**: zip the three slices, and LLVM vectorizes the loop the way clang
does.

```rust
next[..w].copy_from_slice(&best[..w]);
for ((slot, &keep), &base) in next[w..].iter_mut().zip(&best[w..]).zip(&best[..=cap - w]) {
    *slot = keep.max(base + item.value);
}
std::mem::swap(&mut best, &mut next);
```

**Go** vectorizes nothing on its own, so write the lanes with
`simd/archsimd`. Once per item, `v := archsimd.BroadcastInt64x4(it.Value)`;
then for each four budgets from `w` up, load
`keep := archsimd.LoadInt64x4(best[c:])` and
`take := archsimd.LoadInt64x4(best[c-w:]).Add(v)`, and store
`keep.IfElse(keep.Greater(take), take)` into `next[c:]`. A scalar loop takes
the last `(capacity + 1 - w) % 4` budgets.
