# Complexity — the same work in a different shape

`golden/solution.c` and hint 2's one-row loop both run in
`O(items × capacity)` time; the second row costs `O(capacity)` more memory.
They compute the same cells from the same recurrence. The difference is the
loop body: the one-row loop loads, adds, compares, and stores one budget at a time, gcc with a branch on a
compare that depends on the data and clang with a conditional move. `golden/`
handles four budgets per instruction with no branch in the loop.

Measured on this box — Ryzen 9 5950X, `-O3 -march=x86-64-v3`, 1000 items and
capacity `10^4` (the README's limits), best of 50 calls to `solve` pinned to one
core:

| items | `golden/` gcc 12.2 | `golden/` clang 21 | one row, gcc 12.2 | one row, clang 21 |
|---|---|---|---|---|
| weights 1–1000, values 1–1000 | 1.68 ms | 1.40 ms | 6.42 ms | 4.37 ms |
| weights 1–50, values 1–100 | 1.69 ms | 1.43 ms | 5.54 ms | 4.51 ms |
| weights up to capacity/3, values up to `2^31 − 1` | 1.65 ms | 1.49 ms | 5.35 ms | 3.87 ms |

Two and a half to four times faster under the same compiler, for no less work.
gcc's vectorized one-row loop, the middle row of hint 5's table, takes 2.0 to
2.5 ms: walking downward, it reverses every vector it loads and stores with
`vpermq`.

`make vec` sees the same thing without a clock. Traced on the fixture,
`golden/` retires 0.01 scalar and 0.61 packed instructions per item-capacity
pair, and the one-row loop passes the one-scalar budget before it finishes,
under gcc 12.2 and clang 21 alike, at the default tuning and with
`-mtune=skylake` or `-mtune=znver3`: its wall is the conditional store in one
row, not a cost model.
