# Hint 4 — Level 3

> Spoilers for `make vec`. Levels 1 and 2 need none of them. Open only when
> stuck, and only one file at a time.

**The algorithm is not the problem.** A `solve` that passes `make bench` already
does the right amount of work. `make vec` asks whether the compiler could do it
four budgets at a time, and that depends on the shape of the inner loop.

Ask the compiler. From `c/`, with hint 2's loop written as
`if (take > best[c]) best[c] = take;`:

```
gcc -O3 -march=x86-64-v3 -I../../shared/c -fopt-info-vec-missed -c solution.c -o /dev/null
clang -O3 -march=x86-64-v3 -I../../shared/c -Rpass=loop-vectorize -c solution.c -o /dev/null
```

gcc 12 reports `missed: couldn't vectorize loop`. clang 21 reports
`vectorized loop (vectorization width: 4, interleaved count: 4)`, and
`make vec` still grades it scalar. Read
what clang emitted just before its vector loop: a run-time check that decides
which copy of the loop runs.

What does that check have to establish? Iteration `c` reads `best[c - w]` and
writes `best[c]`, in the same array. What would the loop have to look like for
the compiler to have nothing left to check?
