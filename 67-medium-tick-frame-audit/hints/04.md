# Complexity — the same work in a different shape

Both implementations run the same three compares on every byte and return the
same answer: `O(bytes)` time for both, plus `O(width)` extra space for the
template. There is no asymptotic gap to hide behind.

`golden/` wins because the inner loop's trip count is `width` and every
operand's address follows from the loop index alone, so thirty-two consecutive
bytes can be classified side by side. The control's cursor makes byte `i + 1`'s
offset depend on byte `i`'s, and its `switch` is control flow gcc will not fold
into a select; either one alone keeps the loop scalar under gcc, and the cursor
alone keeps it scalar under clang.

Measured on this box — Ryzen 9 5950X, `-O3 -march=x86-64-v3`, a 1 MiB stream
with six separators per frame, best of 30 calls to `solve`:

| width | gcc `golden/` | gcc `rotten/` | clang `golden/` | clang `rotten/` |
|---|---|---|---|---|
| 13 | 850 µs | 823 µs | 281 µs | 2186 µs |
| 24 | 343 µs | 894 µs | 246 µs | 2176 µs |
| 32 | 119 µs | 816 µs | 180 µs | 2268 µs |
| 64 | 103 µs | 841 µs | 146 µs | 2151 µs |
| 128 | 93 µs | 1136 µs | 137 µs | 2204 µs |
| 512 | 86 µs | 827 µs | 133 µs | 2292 µs |

Below one vector's width the frame-major loop never fills a vector: at width
13, gcc's version of it runs no faster than the cursor. That is why the
constraints start at 32 bytes, where every frame holds at least one full
32-byte block.

`make vec` sees the same thing without a clock. Traced on fixture `15`,
`rotten/` retires 9 scalar instructions per byte under gcc and 22 under clang,
and `golden/` 0.06 and 0.15.

This is the shape a feed handler ends up with once the per-byte `switch` shows
up in a profile. A fixed-width layout exists so that record boundaries and
field offsets are known before a byte is read; the handler that still
discovers them by walking a cursor pays for state it already had.
