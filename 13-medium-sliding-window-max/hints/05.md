# Hint 5 — Level 3

> Spoilers for `make vec`. Levels 1 and 2 need none of them. Open only when
> stuck, and only one file at a time.

**The deque clears the bench and fails `make vec`.** Look at what it does per
reading: pop from the back while the back is not bigger, push, maybe pop the
front. How many pops a reading costs depends on the readings before it, so
eight readings cannot take the same steps side by side, and the loop is all
branches on values.

Confirm that this is where it stops. From `c/`, with a deque `solve`,
`cc -O3 -march=x86-64-v3 -I../../shared/c -fopt-info-vec-missed -c solution.c
-o /dev/null` has gcc 12.2 report `not vectorized: control flow in loop.` for
both loops, and clang 21's `-Rpass-analysis=loop-vectorize` says `Cannot
vectorize potentially faulting early exit loop` about the pop loop. `make vec`
grades a C deque at about 20 scalar instructions per reading.

So look for a linear-time method that does the same work at every reading
whatever the values are. The window length `k` is the one thing that never
changes: what boundaries in the array can you fix before reading a single
value?
