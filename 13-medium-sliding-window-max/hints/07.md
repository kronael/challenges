# Hint 7

**The combine vectorizes; the two scans do not.** Write hint 6 the direct way:

```c
for (size_t lo = 0; lo < n; lo += k) {
	const size_t hi = lo + k < n ? lo + k : n;
	pre[lo] = arr[lo];
	for (size_t i = lo + 1; i < hi; i++) {
		pre[i] = arr[i] > pre[i - 1] ? arr[i] : pre[i - 1];
	}
	/* suf: the same, from hi - 1 down to lo */
}
for (size_t i = 0; i + k <= n; i++) {
	peak[i] = suf[i] > pre[i + k - 1] ? suf[i] : pre[i + k - 1];
}
```

The last loop is an element-wise maximum of two arrays, and gcc and clang both
turn it into `vpmaxsd` over eight readings at a time. The scans stay scalar:
`pre[i]` needs `pre[i - 1]`, so reading `i + 1` cannot start before reading `i`
is done. gcc 12.2 reports `not vectorized, possible dependence between
data-refs` for each scan; clang 21 reports `value that could not be identified
as reduction is used outside the loop` — a running maximum that is stored at
every step is not a reduction. gcc even computes the scan with `vpmaxsd`, but
on one lane: a `vmovd` load, the max, a `vmovd` store, per reading.

`make vec` grades this form at 8.03 scalar instructions per reading under gcc
and 7.54 under clang. The two scans are two loads, two stores, and a handful of
compares and moves per reading; the vectorized combine cannot pay for them.

So the question is how to take a running maximum across eight lanes at once.
Within one vector it is the prefix problem that parallel hardware solves in
logarithmic depth: after how many shift-and-max steps does lane `7` hold the
maximum of lanes `0..7`? And what has to change when a block starts in the
middle of a vector?
