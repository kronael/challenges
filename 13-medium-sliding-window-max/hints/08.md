# Complexity — more work, all of it in lanes

Doubling takes `O(n log k)` time and `O(n)` extra space, against the deque's
`O(n)`: at the limits, `2·10⁵` readings with `k = 2·10⁵`, that is 17 passes.
Each pass is one packed maximum per eight 32-bit readings, or per four 64-bit
ones, and the loop control inside a vector loop is not counted, so the passes
add a fraction of a scalar instruction per reading between them. The bench
does not mind the logarithm either.

Traced on `vec.in`, 30011 readings with `k = 1237`, ten passes:

| `solve` | scalar per reading |
|---|---|
| `golden/`, 32-bit, gcc 12 / clang 21 | 0.03 / 0.02 |
| C scaffold, `long long`, gcc 12 / clang 21 | 0.03 / 0.02 |
| Rust, the zipped loop, rustc 1.97 | 0.02 |
| Go, `archsimd` over `[]int32`, Go 1.27.1 | 0.03 |
| in place, gcc 12 / clang 21 | 0.03 / over 1 |
| deque, C, gcc 12 / clang 21 | over 1 / over 1 |
