# Hint 8 — read one array, write another

Updated in place, `span[i] = max(span[i], span[i + w])` is correct one reading
at a time, and gcc 12 vectorizes it. clang 21 reports the loop vectorized too,
but puts a run-time check in front of the vector loop that the range it reads,
from `span[w]`, and the range it writes, from `span[0]`, do not overlap. In
place they do, so clang runs its scalar copy and `make vec` grades it scalar.
Two arrays that swap after each pass leave nothing to check:

```c
for (; 2 * w <= k; w *= 2) {
	for (size_t i = 0; i + 2 * w <= n; i++) {
		next[i] = span[i] > span[i + w] ? span[i] : span[i + w];
	}
	/* swap span and next */
}
for (size_t i = 0; i + k <= n; i++) {
	peak[i] = span[i] > span[i + k - w] ? span[i] : span[i + k - w];
}
```

**C**: the scaffold's readings are `long long`. AVX2 has no 64-bit maximum, so
gcc and clang compare and blend four lanes at a time.

**Rust**: zip the slices, and LLVM vectorizes the loop the way clang does.

```rust
for ((out, &a), &b) in next[..len].iter_mut().zip(&span[..len]).zip(&span[w..]) {
    *out = a.max(b);
}
std::mem::swap(&mut span, &mut next);
```

**Go** vectorizes nothing on its own, so write the lanes with
`simd/archsimd`: for each eight readings,
`archsimd.LoadInt32x8(a[i:]).Max(archsimd.LoadInt32x8(b[i:])).Store(dst[i:])`,
then a scalar loop for the last `len % 8`. One helper serves every pass and the
combine.
