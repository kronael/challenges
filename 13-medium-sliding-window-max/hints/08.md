# Approach — the block filter, with its scans in lanes

Hint 6 is the van Herk / Gil–Werman filter. Its combine vectorizes as written;
the scans need the running maximum computed inside a vector, three
shift-and-max steps deep, with the previous vector's result carried in.

## A running maximum across eight lanes

```c
static __m256i rise(__m256i v) {
	const __m256i low = _mm256_set1_epi32(INT32_MIN);
	v = _mm256_max_epi32(v, _mm256_alignr_epi8(v, low, 12)); /* lane j-1 */
	v = _mm256_max_epi32(v, _mm256_alignr_epi8(v, low, 8));  /* lane j-2 */
	const __m256i third = _mm256_setr_epi32(0, 0, 0, 0, 3, 3, 3, 3);
	return _mm256_max_epi32(v, _mm256_permutevar8x32_epi32(v, third));
}
```

`vpalignr` shifts inside each 128-bit half and fills with `INT32_MIN`, which no
maximum can pick, so after two steps every lane holds the maximum of its half up
to itself. One `vpermd` then hands lane `3` to the upper half. For `pre`, a
vector whose eight readings sit in one block is `max(rise(v), carry)`, where
`carry` is the previous vector's lane `7` broadcast to all lanes — or
`INT32_MIN` when this vector opens the block. The next carry is
`max(carry, rise(v)[7])`: one `vpmaxsd` on the loop-carried chain, with the
broadcast off it. `suf` is the mirror, walking down with `alignr(low, v, 4)`,
`alignr(low, v, 8)`, and lane `4` handed to the lower half.

## When a block starts inside a vector

Keep `off`, a vector holding each lane's position in its block,
`(i + j) mod k`. Every shift by `d` lanes is then kept only where it does not
cross a block start — `off > d − 1` — and the carry only where the block began
before this vector — `off > j`:

```c
v = fold(v, _mm256_permutevar8x32_epi32(v, back1), _mm256_cmpgt_epi32(off, zero));
v = fold(v, _mm256_permutevar8x32_epi32(v, back2), _mm256_cmpgt_epi32(off, one));
v = fold(v, _mm256_permutevar8x32_epi32(v, back4), _mm256_cmpgt_epi32(off, three));
v = fold(v, carry, _mm256_cmpgt_epi32(off, lanes));
```

with `fold(v, from, take) = max(v, blendv(v, from, take))` and `back1` =
`0 0 1 2 3 4 5 6`, `back2` = `0 0 0 1 2 3 4 5`, `back4` = `0 0 0 0 0 1 2 3`. A
lane that asks for a lane below `0` gets lane `0`, which is harmless: if the
mask lets it through, lane `0` is in the same block and already counted. This
form is right for any `k`, including `k < 8`, where one vector holds several
block starts.

Moving eight readings on, `off` becomes `(off + 8 mod k) mod k`. Both terms are
below `k`, so compute `off + step` and `off + step − k` side by side and keep
the unsigned minimum (`vpminud`): when the sum is below `k`, the difference is
negative, which reads as a huge unsigned number.

`golden/solution.c` runs the unmasked `rise` when all eight readings share a
block — a scalar `at = i mod k` decides, and on the fixture that is most
vectors — and the masked form otherwise. The last `n mod 8` readings of each
scan are scalar. `make vec` grades it at 0.03 scalar instructions per reading
under gcc 12.2 and 0.02 under clang 21, with about 3 packed instructions per
reading, at each compiler's default tuning and at `-mtune=skylake` and
`-mtune=znver3`; hint 7's form stays scalar at all of them.

The masked form alone is correct everywhere and grades vectorized too, at about
5 packed instructions per reading; the unmasked path is only there for speed.

## Rust, Go, and C

**Rust**: the same intrinsics live in `std::arch::x86_64`, with the byte shift
as `_mm256_alignr_epi8::<12>(v, low)`. Call them from an `unsafe` block.
`make test` and `make bench` run them in the debug build as plain calls, and
`make vec` builds with `-C target-cpu=x86-64-v3`, where they inline;
`#[target_feature]` is neither needed nor accepted. Measured with rustc 1.97: a
port of `golden/` grades 0.02 scalar instructions per reading, against 10.28
for hint 7's form over `chunks_mut(k)`; a `VecDeque` deque is scalar too.

**Go** vectorizes nothing on its own, so all three passes go through
`simd/archsimd`, the combine included, in 32-bit lanes:
`archsimd.LoadInt32x8(a[i:])` and `Store`, `Int32x8.Permute` with a `Uint32x8`
of indices for the shifts (`vpermd`), `Greater` for the masks,
`from.IfElse(take, v)` for the blend, `Max`, and `AsUint32x8().Min` for the
offset step. The masked form alone, written that way over an `[]int32`, grades
0.03 to 0.04 scalar instructions per reading with Go 1.27.1, against about 28.5
for a slice-based deque or hint 7's form. The scaffold hands `solve` an
`[]int`, though, and a plain loop that narrows it costs a load and a store per
reading, two scalar instructions against a budget of one. Narrow in lanes too —
view two `Int64x4` as `Int32x8` and gather their low halves with a permute —
and widen the answers back with `Int32x4.ExtendToInt64`.

**C**: the scaffold's readings are `long long` too. Narrow them into an
`int32_t` array first — gcc and clang vectorize that loop — run the scans
above, and widen the answers back: 0.03 scalar instructions per reading under
gcc. `make test` and `make bench` build `c/` for baseline x86-64, where AVX2
intrinsics do not compile; only `make vec`'s build defines `__AVX2__`, so keep
another `solve` in the `#else` for the baseline build. `make vec` checks every
case on its own build.
