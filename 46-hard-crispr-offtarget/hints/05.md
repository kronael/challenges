# Hint 5 — Level 3

> Spoilers for `make vec`. Levels 1 and 2 need none of them. Open only when
> stuck, and only one file at a time.

**Count what the index costs per base.** `make vec` charges every load and
store of 64 bits or less that does not address the stack, wherever it runs.
Building the seed index puts each window's start into the bucket of each of its
`d + 1` seeds. The bucket depends on the seed, and x86-64-v3 has no scatter
store, so each of those writes is a store of one element: at least `d + 1`
scalar stores per base before a single guide is looked up. Nothing done beside
the index brings that back under one per base.

Level 3 wants work of another shape: the same few operations for every window
and every guide, with no address that depends on the data. Scanning every
window against every guide has that shape, and hint 4 shows it is too slow when
it compares one base at a time. How many bases of a window can one machine word
compare at once?
