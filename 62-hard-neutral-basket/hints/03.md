# Approach — meet in the middle: two halves, one sorted, one binary search

This is **meet in the middle** (Horowitz–Sahni), the standard answer to a
subset problem whose values are too large to index but whose count is small
enough to halve. Split the positions into two halves, enumerate each half's
subset nets in full, sort one side, and binary-search it once per net of the
other side.

**Build a half's nets by doubling.** Start with the single net `0` — the empty
choice — and fold in one position at a time: every net you already have either
takes the new position or does not.

```
nets(values):
    totals = [0]
    for value in values:
        totals = totals + [t + value for t in totals]
    return totals            # 2^len(values) entries, totals[0] == 0
```

That is `1 + 2 + 4 + ... + 2^h = 2^(h+1) - 1` additions for a half of size `h`,
so building both halves costs `O(2^(n/2))` — cheaper than the sort that follows.

**Then sort one side and search it.**

```
middle = n / 2                      # 19 and 19 at n = 38; 8 and 9 at n = 17
front  = nets(exposures[0 .. middle))
back   = sorted(nets(exposures[middle .. n)))

best = |target|                     # the empty basket: front 0 paired with back 0
for f in front:
    want = target - f
    i    = lower_bound(back, want)  # first index with back[i] >= want
    if i < len(back):  best = min(best, back[i] - want)      # nearest from above
    if i > 0:          best = min(best, want - back[i - 1])  # nearest from below
print best
```

Both branches are guarded and both are needed. `lower_bound` can legitimately
return `0` (every net in `back` is above `want`, so there is nothing below) or
`len(back)` (every net is below it, so there is nothing above). Fixtures `05` and
`07` are exactly those two shapes, and each one crashes or silently misses if you
keep only one of the two comparisons.

Note what `best = |target|` is doing: it is not a special case for the empty
basket, it is the pair `(0, 0)`, which the loop would find on its own since
`0` is in both halves. Seeding `best` with it just saves an "is best set yet"
test in the inner loop.

**The two-pointer alternative.** Sort `front` ascending and `back` descending,
then walk them with two cursors: at `(f, b)`, if `f + b > target` step the `back`
cursor down, otherwise step the `front` cursor up, recording `|f + b - target|`
at every step. Each cursor only moves forward, so after the two sorts the scan is
linear rather than `2^(n/2)` logarithms. It measures about the same as the binary
search here because the sorts dominate either way; take whichever you can write
without an off-by-one.

**Things that go wrong.**

- **Only searching within a half.** The optimum routinely needs positions from
  both halves — fixture `16_split_spanning_pair` can only be hit by one position
  from each side, and its ten small middle positions cannot bridge the gap.
- **Forgetting that the empty basket is a basket.** Initialising `best` from a
  non-empty net makes fixture `11_empty_basket_exact` report 7 instead of 0.
  Enumerating only *proper* subsets is the mirror-image bug: it makes fixture
  `12_full_basket_exact` report 2 instead of 0, because dropping any one position
  from that all-positive desk undershoots the mandate by that position.
- **32-bit accumulation.** Nineteen positions at `10^12` overflow a signed 32-bit
  accumulator (`2^31`) roughly 8,800 times over. Fixtures `13_i64_magnitudes` and
  `14_near_limit_cluster` fail loudly; the large cases fail silently with a
  plausible-looking wrong number.
- **De-duplicating, or reaching for a hash set.** Equal nets are harmless — the
  binary search does not care, and dropping them buys nothing on the seeded cases
  where all 38 exposures are distinct. A hash set, by contrast, answers the wrong
  question: it finds `target - f` exactly or not at all, and both large cases have
  a non-zero answer.
- **Recursing to enumerate a half.** A `2^19`-leaf recursion is fine on depth
  (19 frames), but per-call allocation of a list of nets is not; build the halves
  iteratively as above and each half is one array of `2^19` 64-bit integers, 4 MB.

An early `if best == 0: break` is legitimate and costs nothing, but do not count
on it: both seeded large cases answer non-zero, so the full sweep runs.
